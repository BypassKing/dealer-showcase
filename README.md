# 二手车展示与销售专属链接系统

文档更新日期：2026-11-09。当前 `package.json` 版本：`1.0.0`。

本项目使用 Node.js、Express 和原生 HTML/CSS/JavaScript，面向二手车展示和客户分享场景，不使用 WordPress。一个中文后台管理同一套车辆库，每个销售人员通过自己的专属链接展示车辆，并使用自己的电话和 WhatsApp 联系客户。

前台以英语为基础，提供八种语言选项，适配 PC 和手机 H5。业务流程是浏览车辆、查看详情、联系销售或提交卖车咨询，无支付、订单结算或客户会员流程。

本文按当前仓库源码整理；上传文件并重启项目后，服务器才会使用对应版本。多套非洲市场模板及销售链接选择模板目前处于规划阶段，当前仍使用一套固定前台模板。

## 3. 宝塔首次部署

操作在宝塔服务器上完成，电脑端只需要上传源码和访问浏览器。

### 第 1 步：准备运行环境

在宝塔安装 Nginx 和 Node.js 项目管理器，选择 Node.js 22 或 24。代码最低要求 Node.js 18；本项目使用 ES Modules，无前端构建步骤。

### 第 2 步：上传源码

示例项目路径：

```text
/www/wwwroot/autohaven
```

上传 `server.js`、`package.json`、完整的 `lib/` 和 `public/`，保留目录层级。`README.md` 可一并上传；`tests/` 用于开发检查，可不传。

品牌图标依赖 `public/brand-logos.js` 和 `public/brand-logos/`，只上传 `app.js`、`style.css`、`index.html` 无法完成首次部署。

### 第 3 步：创建 .env

在项目根目录创建名为 `.env` 的 UTF-8 文本文件，与 `server.js` 放在同一级，避免保存成 `.env.txt`。可以在宝塔文件管理器开启隐藏文件显示后编辑。

```dotenv
PORT=3000
NODE_ENV=production
ADMIN_PASSWORD=替换为你自己的初始密码
SESSION_SECRET=替换为生成的随机字符串
```

将两个中文占位值替换为真实配置。密码建议至少 12 位；后台新建账号和修改密码接受 8 至 128 个字符。

在宝塔终端生成会话密钥后，复制输出填入 `SESSION_SECRET`：

```bash
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

| 配置项 | 用途 |
| --- | --- |
| `PORT` | Node 服务端口，默认 3000，须与宝塔项目及反代目标一致 |
| `NODE_ENV` | 运行环境，部署时填写 `production` |
| `ADMIN_PASSWORD` | 首次创建超级管理员的密码，或显式重置时使用的密码 |
| `SESSION_SECRET` | 登录令牌签名密钥，保持固定并妥善保存 |
| `ADMIN_PASSWORD_RESET` | 临时密码重置开关，平时删除此项或设置为 `false` |

程序启动时自行读取根目录 `.env`，宝塔界面没有“环境变量”选项也可以部署。宝塔进程已经设置的同名环境变量优先于 `.env`，修改配置时先确认两处是否重复。

已有管理员账号时，单独修改 `ADMIN_PASSWORD` 不会覆盖当前密码。未配置该变量时源码存在固定后备密码，因此首次启动前务必填好自己的密码。

### 第 4 步：安装依赖

在宝塔终端进入项目目录，使用选定 Node.js 版本对应的 npm：

```bash
cd /www/wwwroot/autohaven
node -v
npm -v
npm install --omit=dev
```

当前仅有 Express 和 Multer 两个直接依赖。若终端找不到 `node` 或 `npm`，在宝塔 Node.js 管理器中设置命令行版本后重新打开终端。

当前仓库未提供 `package-lock.json`，首次部署使用上面的 `npm install`。安装后生成的锁文件可纳入后续发布流程；只有锁文件与 `package.json` 一致时才使用 `npm ci --omit=dev`。

### 第 5 步：添加 Node.js 项目

在宝塔 Node.js 项目管理器填写：

| 项目 | 值 |
| --- | --- |
| 项目目录 | `/www/wwwroot/autohaven` |
| 启动文件 | `server.js` |
| 启动命令（面板要求时填写） | `npm start`，等价于 `node server.js` |
| 运行端口 | `3000` |
| 运行环境 | `production` |
| 实例数量 | `1` |

面板按“启动文件”或“启动命令”其中一种方式托管即可，避免重复启动占用同一端口。当前登录会话保存在进程内存中，应使用单实例；Node 项目重启后，管理员需要重新登录。

程序会创建数据和照片目录。运行 Node 的用户需要拥有这两个目录的读写权限；上传源码的父目录也需要允许首次创建子目录。可在宝塔文件管理器中设置对应运行用户，避免直接使用全目录 `777`。

### 第 6 步：绑定域名、配置反向代理和 HTTPS

在宝塔“网站”中添加域名，反向代理目标填写：

```text
http://127.0.0.1:3000
```

将整站路径转发给 Node，保证 `/sales/lt`、`/api/`、`/uploads/` 和静态资源都能到达项目。不要把站点仅配置为读取 `public/index.html` 的纯静态网站。

为域名申请并启用 HTTPS。下面是放在现有 Nginx `server` 块内的配置示例；若宝塔已经生成 `location /`，修改现有规则，避免重复添加同名规则：

```nginx
client_max_body_size 256m;

location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Host $http_host;
    proxy_set_header X-Forwarded-Host $http_host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 120s;
    proxy_send_timeout 120s;
    proxy_cache off;
}
```

256MB 的请求体上限用于容纳最多 20 张、每张 12MB 的批量照片及表单开销。若启用 CDN 或额外代理，还需要检查其单次上传限制；遇到限制时可分批追加照片。

HTTP 直接访问也可以登录：当前代码根据请求协议决定是否给 Cookie 添加 `Secure`，并非只要 `NODE_ENV=production` 就禁止 HTTP。正式域名使用 HTTPS，并确保 `Host` 和 `X-Forwarded-Proto` 传递正确。

使用上述反向代理后，客户通过域名的 80/443 端口访问即可，无需对公网开放 3000。若临时使用 `http://服务器IP:3000`，云服务器防火墙和系统 UFW 都要允许该端口。

### 第 7 步：检查启动和首次登录

在宝塔终端执行：

```bash
curl -I --max-time 5 http://127.0.0.1:3000/
ss -lntp | grep ':3000'
```

第一个命令应返回 `200 OK`，第二个应看到 Node 正在监听。浏览器打开 `https://你的域名/#/admin`，全新安装时账号为 `admin`，密码为首次启动前配置的 `ADMIN_PASSWORD`。

根地址内容区空白是当前设计；部署完成后通过后台和销售专属链接检查业务页面。首次数据中的 A/B/C 销售人员、电话和示例车辆需在正式分享前替换为自己的资料。

## 4. 后台使用

### 4.1 车辆新增与编辑

“车辆管理”的添加和编辑共用弹窗表单，按基本信息、车辆描述、照片等区域填写。至少填写一个中文或英文标题；面向海外客户时，同时填写英文标题和英文描述。

当前可录入品牌、车型、车型分类、年份、里程及单位、价格及币种、变速箱、排量、燃料、驱动方式、方向盘、车况、所在地、状态和推荐标记。排量可填写 `1.5L`、`2.0T` 或 `1498cc`。

PHEV 位于“燃料类型”，表示插电式混合动力；“驱动方式”保持 FWD、RWD、AWD、4WD。品牌从后台品牌库选择，可先添加新品牌再添加车辆。

币种支持 USD、NGN、IDR、THB、MYR、PHP、VND。价格填写纯数字，货币由独立字段选择。当前按原始金额显示，不自动换汇。

保存成功后列表会重新读取。照片顺序会额外请求单车接口核验；若提示资料已提交但核验失败，关闭弹窗后刷新核对，避免重复上传同一批照片。

### 4.2 照片、排序与首图

- 格式：JPEG、PNG、WebP、GIF；每辆车最多保留 20 张，每张不超过 12MB。
- 支持多次选择并追加照片，编辑时保留原有已保存照片。
- 电脑端拖动卡片排序，手机端使用“前移 / 后移”。
- 点击“设为首图”会将该照片移动到第一位；列表封面及详情第一张使用相同顺序。
- 调整后需要点击“保存车辆”或“保存修改”才会持久化。
- 尚未保存的新照片可移除；当前未提供逐张删除已保存照片的操作。
- 新增车辆时可填写一条 HTTP/HTTPS 图片地址参与排序；HTTPS 页面优先使用 HTTPS 图片，避免混合内容被浏览器拦截。

车辆详情支持缩略图切换、电脑左右按钮、画廊获得焦点时的左右方向键，以及手机横向滑动。

### 4.3 品牌管理

“车辆品牌”支持添加、编辑和删除。添加与编辑均使用弹窗，电脑双列、手机单列；可通过右上角关闭、取消、Esc 或遮罩关闭。保存失败时保留已填内容。

填写英文品牌名、中文品牌名、唯一品牌标识和可选 HTTPS 图标地址。标识使用小写字母、数字及短横线，例如 `toyota`、`mercedes-benz`。

前台中文品牌筛选使用中文名称，其余语言通常使用英文品牌名。自定义图标优先于内置图标；缺少图标或图片加载失败时显示名称首字母。被车辆使用的品牌无法直接删除；修改品牌名称时，服务端会同步更新精确匹配原中英文名称的车辆品牌字段。

内置 SVG 图标及来源记录位于 `public/brand-logos/` 和 `public/brand-logos-sources.txt`，运行时从本站读取。

### 4.4 销售人员专属链接

在“销售链接”新建或编辑销售人员，填写链接标识、名称、电话和 WhatsApp。电话、WhatsApp 建议填写包含国家区号的完整号码。

示例标识 `lt` 对应 `/sales/lt`。同一车辆在不同销售链接下展示相同资料，但顶部电话和详情联系按钮使用当前销售人员信息。

可以复制链接、编辑资料或删除链接；销售链接数量可按业务需要创建，没有必须保留三条的限制。每个链接当前使用同一套模板，后台尚无模板选择项。

通过 HTTPS 可使用浏览器剪贴板接口；HTTP 下有旧式复制回退，仍可能受浏览器权限限制，届时可手动复制完整地址。

### 4.5 卖车咨询

客户在销售页面“卖车”表单填写姓名、电话、品牌车型、年份里程及说明，提交后可在后台“卖车咨询”查看和删除。

当前最多保留最近 500 条记录，尚无搜索、处理状态编辑、备注、导出、销售人员归属或自动消息通知。记录保存后不会自动向 WhatsApp 或邮箱发送信息。

### 4.6 管理员与密码

| 角色 | 权限 |
| --- | --- |
| 超级管理员 | 管理车辆、品牌、销售链接、咨询及其他管理员账号；修改自己的密码 |
| 普通管理员 | 管理车辆、品牌、销售链接、咨询；修改自己的密码；管理范围覆盖同一套数据 |

新建账号为普通管理员，不会按销售链接隔离数据。超级管理员可编辑账号名称、登录账号、重设密码和停用账号；当前账号和超级管理员无法被停用，后台未提供删除管理员入口。

账号为 3 至 32 位字母、数字、下划线、点或短横线，以字母或数字开头，保存时统一转成小写。新密码为 8 至 128 个字符。

修改自己的密码需要当前密码及两次一致的新密码，成功后重新登录。重设密码、停用账号或修改登录账号会使该账号已有会话失效；普通会话有效期为 8 小时，项目重启同样需要重新登录。

从旧的仅密码版本升级时，首次迁移创建 `admin` 账号并沿用旧密码；已经存在的管理员账号和业务数据继续保留。

### 4.7 忘记超级管理员密码

1. 在服务器根目录 `.env` 设置新的 `ADMIN_PASSWORD`，并临时添加 `ADMIN_PASSWORD_RESET=true`。若宝塔配置了同名变量，先同步处理，避免 `.env` 被覆盖。
2. 在宝塔重启 Node 项目一次。
3. 查看日志，确认出现 `Admin password reset from ADMIN_PASSWORD`。
4. 删除 `ADMIN_PASSWORD_RESET` 这一行，或设为 `false`，再次重启。
5. 使用超级管理员当前账号和新密码登录；只有全新安装或旧密码版本迁移时账号默认是 `admin`。

该操作重置第一个启用中的超级管理员密码，不改变账号名称，也不删除车辆或销售链接。不要通过删除 `data/site.json` 重置密码。

登录失败累计达到同一来源 IP 的 10 次后，会提示等待 15 分钟；先确认账号、实际配置来源及重置日志，避免持续重复提交。

## 5. 多语言与筛选规则

### 5.1 界面语言

| 代码 | 语言 |
| --- | --- |
| `en` | 英语 |
| `zh` | 简体中文 |
| `id` | 印尼语 |
| `th` | 泰语 |
| `ms` | 马来语 |
| `fil` | 菲律宾语 |
| `vi` | 越南语 |
| `ha` | 豪萨语 Hausa |

后台固定中文；前台语言下拉框支持手动切换，并在当前浏览器的 `localStorage` 中以 `dealer-language` 保存选择。该选择在同一域名的销售链接之间共用。

没有已保存的手动选择时，前台调用 `/api/locale`，服务端读取 Cloudflare 的 `CF-IPCountry` 国家请求头：CN→中文、NG→豪萨语、ID→印尼语、TH→泰语、MY→马来语、PH→菲律宾语、VN→越南语，其余默认英语。

当前 Node 服务没有独立 IP 地理库；普通宝塔 Nginx 反代不会自行产生国家请求头。只有可信代理根据访客 IP 注入该头时，才能按国家自动选择语言。经过 Cloudflare 时需要启用相应 IP 地理信息请求头；没有该头时回退英语，用户仍可手动切换。

尼日利亚当前映射为豪萨语，这是现有代码规则，客户也可切换英语。八种语言选项已经接入，但部分静态文案或自由填写字段仍可能回退英语或原文，不代表任意内容都会自动翻译。

### 5.2 车辆标题和描述

后台当前直接编辑中文和英文标题、描述。读取车辆内容的顺序是：

```text
当前语言字段 → 英文字段 → 原始字段
```

例如中文读取 `title_zh`，印尼语优先读取 `title_id`，没有时读取 `title_en`，再回退 `title`；描述同理。后台尚无六种其他语言的独立输入框，也未接入自动翻译服务，因此只填写中文时，切换外语仍可能看到中文。

车型分类、燃料、驱动方式和方向盘等枚举使用内置词条；自由填写的变速箱、所在地及描述按已有内容显示。

### 5.3 筛选范围

年份筛选按具体年份展示，从 2015 年至访问时的当前年份，倒序排列并随年份自动增加。它只限定筛选选项，不会删除或自动隐藏库存中的旧年份车辆；“不限年份”仍展示全部符合其他条件的记录。

价格区间为低于 10,000、10,000 至不足 20,000、20,000 至不足 30,000、30,000 及以上。排序可解析 `$24,800`、`32,400 mi` 等历史格式的数值，但价格筛选和排序尚未做跨币种换算，里程排序也未统一 km/mi 单位。希望数值可直接比较时，应统一车辆的报价币种和里程单位。

## 6. 更新现有服务器

### 更新前备份

在宝塔中停止 Node 项目，备份同一时点的整个项目目录，至少保存 `.env`、`data/` 和 `public/uploads/`。当前数据使用单个 JSON 文件，没有程序内自动备份或事务恢复；使用宝塔备份功能建立可恢复副本。

### 上传文件

完整同步当前功能时，覆盖以下源码，保留子目录结构：

```text
server.js
package.json
lib/admin-auth.js
lib/brands.js
lib/vehicle-photos.js
public/index.html
public/app.js
public/style.css
public/brand-logos.js
public/brand-logos/ 下的全部图标
public/brand-logos-sources.txt
README.md
```

仅覆盖同名源码文件，不要选择“先清空目标目录”或删除整个 `public/`，以免移除线上照片。保留已有 `.env`、`data/`、`public/uploads/`。运行时无需上传 `tests/`。

当前品牌弹窗这一项若从其余功能已同步的版本升级，只需覆盖 `public/app.js`、`public/style.css`、`public/index.html`；跨多个旧版本升级使用上述完整源码清单，避免漏掉后端模块或图标。

### 重启与刷新

1. 依赖有变动时，在服务器运行 `npm install --omit=dev`。
2. 使用宝塔启动或重启 Node 项目，查看日志确认没有缺少模块或端口占用错误。
3. 如使用 CDN、浏览器缓存或宝塔代理缓存，清理相关页面和静态资源缓存；`/api/` 避免缓存，车辆接口及子路径已由 Node 设置 `Cache-Control: no-store`。
4. Windows 浏览器按 Ctrl+F5，Mac 按 Command+Shift+R；手机关闭旧页面后重新打开，必要时清理站点缓存。
5. 重新登录后台，检查销售链接、车辆、照片首图与顺序，再打开销售专属页面核对电话号码和 WhatsApp。

照片排序功能要求前后端同时支持 `photo_order`。只更新前端而保留旧 `server.js` 或旧 `lib/vehicle-photos.js`，可能导致保存后顺序校验失败；应同步文件并重启后再核对。

### 需要回退时

停止 Node 项目，恢复同一备份中的源码、`.env`、数据及照片，然后重新安装匹配的依赖并启动。数据和照片一起恢复，避免 `site.json` 引用的照片与磁盘文件不一致；恢复旧备份会回退该备份之后的数据变更。

## 7. 常见问题

| 现象 | 检查位置与处理 |
| --- | --- |
| 根地址显示空白 | 当前设计；访问 `/#/admin` 或后台生成的 `/sales/标识` |
| 提示找不到 `lib/admin-auth.js` 等模块 | 将完整 `lib/` 目录上传到 `server.js` 同级，并重启项目 |
| 本机 `127.0.0.1:3000` 返回 200，公网仍打不开 | 域名访问检查 Nginx、域名解析和 80/443；直连 3000 则检查云防火墙和 UFW |
| 域名能打开但接口或 `/sales/标识` 失败 | 整站路径需要反代给 Node，保留原路径，避免只有静态首页生效 |
| 账号密码正确仍登录失败 | 确认旧账号是否改过名称、账号是否停用、`.env` 是否被面板变量覆盖；查看重置日志和接口返回的具体错误 |
| 登录后立即回到登录页 | 检查 Cookie 是否被保存、请求域名及 HTTP/HTTPS 是否一致，反代协议头是否正确，以及项目是否频繁重启或运行多个实例 |
| 请求来源错误或跨站提交被拒绝 | 后台与 API 使用同一域名；反代正确传递 `Host`、`X-Forwarded-Host`，避免转发成 `127.0.0.1` 主机名 |
| 上传返回 413 或超时 | 检查 Nginx/CDN 请求体上限和超时；保留每张 12MB、每车 20 张的应用限制，分批追加 |
| 图片顺序保存后未生效 | 同步前端、`server.js`、`lib/vehicle-photos.js`；重启、清缓存并核对接口是否被代理缓存 |
| 品牌只显示首字母 | 检查 `brand-logos.js`、本地图标目录和后台自定义图标地址；部分品牌当前没有内置图标 |
| IP 语言没有变化 | 检查 `/api/locale` 的 `country`、`language`，以及浏览器已保存的手动语言；缺少国家请求头时默认英语 |
| 切换外语后车辆标题仍是中文 | 填写英文标题和描述；当前未提供任意文本自动翻译 |
| 电话不是当前销售人员的号码 | 使用保留 `/sales/标识` 的完整分享链接，并在“销售链接”核对该销售人员电话及 WhatsApp |

node --check public/app.js
node --check public/brand-logos.js
node --check lib/admin-auth.js

使用 Node 内置测试运行器执行品牌、筛选、年份、PHEV、照片首图及排序相关检查，无需额外测试依赖：

node --test tests/brand-filter.test.cjs tests/brands.test.cjs tests/phev.test.cjs tests/vehicle-cover.test.cjs tests/vehicle-photo-manager.test.cjs tests/year-filter.test.cjs

## 9. 已知边界与后续规划

- 当前销售页面只有一套固定模板。已讨论的西非、东非、南部非洲、法语非洲模板和 `templateId` 选择尚未实现；当前无 `/api/sales-templates` 接口。
- 法语、斯瓦希里语、葡萄牙语尚未接入；车辆自由文本没有自动翻译。
- 币种和里程单位尚未统一换算；地区模板也不会自行改变车辆报价。
- 咨询记录尚无销售归属、搜索、备注、导出及通知功能。
- 数据采用单 JSON 文件直接写入，当前没有数据库事务、自动快照或多实例共享会话。
- 删除车辆不会自动清理未引用的上传照片，后台也未提供已保存单张照片的删除和回收站。
- 网站品牌标题及部分介绍文案仍固定在前端源码中，后台没有独立站点设置入口。
- 现有文本转义、密码哈希、登录限制及管理员接口来源检查不代表全系统已完成独立测试；完整的服务端车辆字段校验、所有写接口的来源校验、代理下咨询限流和旧联系人接口整理仍需后续完善。
